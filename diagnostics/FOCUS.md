# 入力欄を一度クリックする診断（0.1.22）

まず操作は「本文入力欄を一度クリックしてフォーカスする」だけに絞ります。入力・名前変更・ツールチップ診断は同時に行わないでください。本文・チャット名・入力値・URLは取得しません。ページをクリック／入力／保存する処理もありません。

1. 対象タブを再読み込みし、Consoleで[focus-latency.js](focus-latency.js)の全文を実行します。
2. **4秒ほど待ってから、ChatGPT本文の入力欄を一度クリック**します。3秒の準備時間後、8秒間だけ測定します。入力は不要です。
3. 実行から12秒ほど経ったら、Consoleで結果をコピーします。

```js
copy(JSON.stringify(window.__ctcFocusDiagnostic, null, 2))
```

`status:complete`、`cleanup:true`で通常終了です。`focus:null`の場合は対象入力欄のフォーカスを取得できていません。すでにフォーカス中だった場合は、実行前にページの空いている場所へフォーカスを外して再度試してください。

同じチャット・同じ幅・同じ拡大率で、次の3条件を比較します。

- **帯ON**：拡張を有効にして対象タブを再読み込み。
- **表示OFF**：popupの表示をOFFにして対象タブを再読み込み。content scriptは動作します。
- **拡張そのものを無効化**：chrome://extensionsでChat Thread Colorsだけを無効にし、対象タブを再読み込み。診断コードは拡張なしでも動きます。

結果に条件名と、操作が重く感じられたかを添えてください。各条件1回からで十分です。比較後は拡張を有効へ戻し、タブを再読み込みしてください。ほかの拡張は変更しないでください。

結果の意味：

- `pointer.dispatchDelayMs`：pointerdownの生成から、この読み取りリスナーが呼ばれるまでの時間。ブラウザの計測条件に依存します。
- `nextFrameMs`：focusinの通知から次のrequestAnimationFrameまで。カーソル描画完了やクリックから操作可能までの全時間を直接測る値ではありません。
- `events`：ブラウザがEvent Timingで報告した入力欄のクリック関連イベント。16ms未満などのイベントは出ない場合があり、空配列だけで「遅延なし」とは断定できません。
- `longTasks`：50ms以上のタスクの時刻と時間。拡張だけの時間ではなく、ページ・他の拡張等も混ざるため、発生源を断定しません。
- `extensionPresent`／`bandVisible`／`layoutActive`：開始時にホスト要素・帯・ページ補正が存在したか。拡張を無効にしても再読み込みしなければ古いcontent scriptが残り得るため、必ず再読み込みします。

タイマー、PerformanceObserver、フォーカス／ポインターのリスナー、フレーム待ちは終了時に解除します。pagehide・手動中止でも解除し、結果は変数に残します。途中停止は次のコードです。

```js
window.__ctcFocusStop?.()
```

通常時の拡張内の処理量まで必要になった場合だけ、別途PERFORMANCE.mdの8秒集計を使います。初回はこのフォーカス1操作の比較を優先してください。
