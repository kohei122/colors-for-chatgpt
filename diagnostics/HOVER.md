# 上部ボタンhover前後の短時間診断（0.1.22・追加調査）

フォーカス診断に代えて、まずこの操作だけを行ってください。既存の処理量診断を使い、12秒で自動停止します。本文・チャット名・ID・入力値・HTML・ツールチップの文言は取得しません。クリック・保存・ページ側スタイルの変更は行いません。結果は拡張ホストの属性に保持されます。

1. 拡張と対象のChatGPTタブを再読み込みし、ページが落ち着くまで待ちます。Consoleで次を実行します。

```js
document.getElementById('marusin-thread-colors')?.dispatchEvent(
  new Event('thread-colors-hover-start')
)
```

2. 実行からの目安で、次の順に操作します。

| 経過 | 操作 |
| --- | --- |
| 0〜3秒 | マウスをボタンから離して待つ |
| 3〜6秒 | 問題の共有・…など、上部ボタン1つにマウスを重ねる |
| 6〜9秒 | マウスを外し、何もせず待つ |
| 9〜12秒 | スクロールや入力欄クリックなど、引っかかる操作をする |

3. 13秒以上経ってから、Consoleでコピーします。遅延でタイマー自体が遅れる場合は`status:complete`になるまで少し待ってください。

```js
copy(document.getElementById('marusin-thread-colors')
  ?.getAttribute('data-performance-diagnostic'))
```

結果と併せて「どのボタン」「消えた後も重かったか」「帯ON/OFF」をお知らせください。チャット名は不要です。操作が表の時刻からずれた場合は、その旨だけ添えてください。区間名は操作を保証するものではなく、実際のtooltip追加・削除のカウンターと併せて判断します。

同じチャット・幅・拡大率で、帯ONと表示OFFを比較できます。必要なら、拡張そのものを無効にして対象タブを再読み込みし、同じhover操作で体感を比較してください。表示OFFでもcontent scriptは動きます。拡張無効時はこの内部診断は使えません。比較後は拡張を有効に戻します。

## 記録するもの

- `phases`：hover前／表示する予定の区間／消滅後の待機／その後の操作。各3秒。
- `signals`：tooltipの追加・削除・属性変更、監視した属性種別、レイアウト祖先の変更、予約理由別のrAF、実行フレーム、モーダル入退場、全体描画、高さ確認・再探索・スタイル参照、タイトルリンク再探索・訪問、定期経路確認の回数。
- `work`：既存のタイトル取得・モーダル確認・高さ確認・DOM監視に加え、モーダル可視性確認の回数・累計・最長所要時間。呼び出しと実作業を分け、`refreshShells`が早期終了した場合も判別できます。
- `longTasks`：ブラウザが報告した50ms以上の処理の時刻と所要時間、最大40件。ページ・他の拡張も含み、拡張への帰属や原因は確定しません。空でも遅延なしとは判断しません。

時間は各処理に入れ子部分も含むため、合計してCPU使用時間とは扱えません。診断中だけ追加のカウンター・所要時間・Long Taskを記録し、12秒で監視を切断します。遷移・pagehide・再開始・以下の中止操作でも解除します。通常時には詳細収集をしません。既存の配置診断・フォーカス診断とは同時に実行しないでください。

```js
document.getElementById('marusin-thread-colors')?.dispatchEvent(
  new Event('thread-colors-performance-stop')
)
```

`schema:2`、`cleanup:true`を確認してください。ツールチップの位置・クリッピング自体はこの診断では測りません。配置問題と重さの共通原因はまだ確認できていません。
