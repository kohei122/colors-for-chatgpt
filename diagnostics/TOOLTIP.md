# 現行1.0.0：通常チャット・Work共通の上部tooltip診断

今回は原因調査の準備です。製品コードは変更していません。以下を現在の手順とし、後半の0.1.xの「再取得不要」「Workだけ」などは過去の記録です。

## 同じ操作を通常チャット・Workで各1回

1. 帯が表示され、症状が出る画面でConsoleを開きます。ウィンドウ幅・拡大率・Consoleの配置は採取中に変えません。設定変更やボタンのクリックは不要です。
2. **開始**：[tooltip-layout.js](tooltip-layout.js)の全文をConsoleに貼り付けて実行します。ファイルを読み込むfetchや外部送信は使いません。
3. **採取**：実行後10秒以内に対象ボタンへマウスを移し、実行後17秒までhoverを維持します。10秒の準備後、6秒間自動採取します。終了後はマウスを外しても採取済み結果は残ります。
4. **状態確認**：次を実行します。通常終了は`complete`かつ`cleanup: true`です。候補が0件でもそのまま保存してください。

```js
({status: window.__ctcTooltipDiagnostic?.status,
  cleanup: window.__ctcTooltipDiagnostic?.cleanup,
  samples: window.__ctcTooltipDiagnostic?.samples.length})
```

採取のための追加コードは不要です。観測中に手動で1サンプル追加する場合だけ次を使えます（Consoleへ移動するとhoverが外れるため、通常は自動採取を使用）。準備中や終了後は採取しません。

```js
window.__ctcTooltipDiagnosticCapture?.()
```

5. **コピー**：Consoleから明示実行します。自動コピーは行いません。

```js
copy(JSON.stringify(window.__ctcTooltipDiagnostic, null, 2))
```

「通常／Work・対象ボタン・上側に出たか」をJSONとは別に添えてください。チャット名やURLは添えないでください。もう一方のモードへ移って、同じ開始・hover・状態確認・コピーを行います。再実行は結果を置き換えるため、先にコピーしてください。

**途中停止・後片付け**（結果は残します）：

```js
window.__ctcTooltipDiagnosticStop?.()
```

終了・停止・遷移検知・pagehide・再実行でタイマーとリスナー、採取／停止関数を解除します。保存した結果も不要になった場合のみ次を実行します。

```js
window.__ctcTooltipDiagnosticStop?.()
delete window.__ctcTooltipDiagnostic;
```

## 今回追加した判定材料と限界

- `assessments[].ariaResolution`：ID文字列を出さず参照先の一致数、数値参照、説明元の数を記録。重複ID、参照欠落、参照過多などを区別します。
- `reasons`：現行コードに照らした観測時の見送り条件。親構造、offsetParent、position、pointer-events、不可視、rotate／scale、帯からの位置、下側の空き不足等を記録します。実際に製品が通過した分岐のログではありません。
- `geometry`：6pxの間隔・端余白を含む下側の空き、必要な高さ、幅、初回観測からの位置・寸法差。折返しが必要な場合は読み取り専用のため折返し後の高さを断定しません。
- `inlineCorrectionEvidence`：translateや折返しプロパティのimportant指定の有無。製品の内部補正状態とスタイル所有者はConsoleから見えないため、適用主体は`unknown-product-private-state`です。translateがあるだけで製品の補正済みとは断定せず、`uncertainties`も確認します。既に補正された後から観測した場合、補正前の矩形は復元できません。250ms未満の変化は採取できない場合があります。
- 既存のARIA対応、親構造、offsetParent、position／display／pointer-events／transform／translate／rotate／scale、操作元とtooltipの矩形、表示領域、帯との交差は引き続き記録します。

製品コードの変更は不要です。内部フラグや補正適用そのものの厳密な実行ログが必要と判明した場合は、計測追加の理由を先に報告します。

最大16秒（タイマーはブラウザの実行状況で遅延し得ます）、最大25個の変化したスナップショットを保持します。クリック・設定変更・スタイル変更・外部送信はしません。本文、チャット名、チャットID、URL全文、自由なラベル文字列は結果に含めません。他の診断とは同時実行しないでください。

## 確認したコードと未確定の原因

帯の表示中はbodyに固定配置、帯の高さ分の上端inset、overflow:auto、transform:translateZ(0)を設定しています。入力欄の画面下へのはみ出しを防ぐための既存処理です。拡張ホストはbodyの外側にあり、z-indexは2147483600です。transformのあるbodyは固定要素の包含ブロックと重なりの階層を作るため、ページ側ツールチップの配置計算や前後関係に関与する可能性があります。

添付実測ではrole=tooltipがdisplay:contentsの親からbody配下にあり、帯ON時はhtml高さ0・side=top・帯と矩形が交差しています。再現画面ではhtml矩形を配置境界にすると同様に反転し、最小高さの確保で解消しました。実ChatGPTが実際に参照する境界・配置アルゴリズムはまだ未確認です。pointer-events:noneなので、ヒットテストに出ないことだけで切り取りや不可視とは断定しません。診断も修正もアイコンのアセット名には依存しません。

## 取得する情報と限界

- 画面上部320 CSS px以内でhover／focusされたボタン（最大4件）、位置・寸法・状態、祖先（最大10階層）。
- aria-describedbyの参照先、role=tooltip、配置ヒント属性を持つ候補（最大24件）。候補というだけで、対応が確認できたツールチップとは断定しません。`triggerRefs`はaria-describedbyで直接対応した場合のみ記録します。
- data-side／align／state等の限定した属性、計算済みのposition・transform・overflow・z-index・表示状態、offsetParent、帯との矩形交差、3点での重なり情報。
- 実際のIDは出さず観測内の連番へ置き換えます。class名、アイコン参照先、aria-labelの自由文字列、ツールチップの文章、タイトル、本文、入力値、URL、HTMLは収集しません。共有ボタンとの一致だけは真偽値で記録します。
- 最大25個の変化したスナップショットだけを保存します。DOM監視は使用せず、準備・観測タイマーとpagehideリスナーは終了時に解除します。クリック・入力変更・保存・通信・ページスタイル変更は行いません。

role=tooltipが読み上げ用の小さな非表示要素で、可視吹き出しがその祖先にあるケースを区別できるよう祖先も取得します。ヒットテストはpointer-events:noneの要素を飛ばすため、ヒット先だけでは「見えない」と断定できません。ブラウザ本来のtitleツールチップや別のShadow DOM内の要素は取得できない場合があります。候補0件の場合はそれ自体を結果として送り、推測でスタイルを変更しないでください。
